## 3. Defect found and fixed

**Dashboard returned 500 in production under any concurrency.**

Supabase's free-tier session pooler allows **15 client connections per
project in total**, shared by every process that connects. The API's pool was
sized at 20, and the dashboard fans out about a dozen queries in parallel.
Two simultaneous dashboard loads, or one load while the absence scan or a
developer's local session held connections, exceeded the cap and the pooler
refused with `EMAXCONNSESSION`, which surfaced as a 500.

Fix: `DB_POOL_MAX` in `server/src/config/env.ts`, with a code-level default
of 8 whenever `DATABASE_URL` points at a Supabase host and 20 elsewhere. The
Render blueprint also sets `DB_POOL_MAX=8`, but the default lives in code
because a variable added to a blueprint did not reach the running service
unprompted. Verified: 20 parallel dashboard loads locally against Supabase
and 10 in parallel on production, all 200.

With 8 connections the pool queues rather than fails; ten simultaneous
dashboards each took about one second on Render. That is the trade the free
tier imposes and it is acceptable for a single church.

## 4. Smaller improvements shipped during the scan

- `/api/health` now reports the running `commit`, so a deploy can be
  confirmed without reading platform logs.
- The regression harness no longer inherits `PGSSL=true` from a `.env` that
  points at a hosted database when its disposable QA database is local.
- Non-breaking dependency updates via `npm audit fix` (lock files only):
  express, body-parser, qs, morgan, multer, nodemailer on the server.

## 5. Known items, not fixed here

| Item | Severity | Note |
|---|---|---|
| `sharp` ≤ 0.35.4 carries libvips and libheif advisories | High | Fix is a major upgrade to 0.35.x; test photo upload and the 512 px re-encode after upgrading. |
| `uuid` via `exceljs` and `node-cron` | Moderate | Needs major upgrades of both; `exceljs` 3.4 is a downgrade path npm suggests and should not be taken. |
| `react-router-dom` 6.x open-redirect advisory | Moderate | Fix is React Router 7, a major upgrade. The app never navigates to user-supplied paths, which is the precondition. |
| O1 from the September review: API connects as the database owner | High (deployment) | On Supabase the `postgres` role is not a superuser but owns every table. A dedicated DML-only role remains the right end state; see `SUPABASE-SETUP.md`, optional hardening. |
| O2: lockout message reveals account existence | Low | Unchanged; both options still documented in the September report. |
| Member photos on Render's ephemeral disk | Medium | Files vanish on restart; database rows survive. Supabase Storage is the recommended fix and a one-file change in `storage.service.ts`. |
| Render free tier sleeps after 15 idle minutes | Low | First request afterwards takes up to a minute. Cosmetic; upgrade only if users find it annoying. |
| Duplicate open follow-up answers 400, API.md implies 409 | Cosmetic | Message is correct; status code choice only. |
